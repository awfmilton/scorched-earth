feat: Contact Trigger and Proximity Fuse

AUDIT.md §3 "Contact trigger / proximity fuse" was MISSING.

The rule, stated once because it decides every edge case: a trigger governs
WHEN the shell first detonates, not what the explosion then does.

- Contact Trigger cancels the families that DELAY the first detonation - roll
  downhill, bounce, dig, tunnel - so the shell goes off where it lands. It does
  not cancel a LeapFrog's hop, because that happens after the first blast
  either way; a test pins that distinction down.
- Proximity Fuse air-bursts within 34px of an enemy hull, turning a near miss
  into a hit. The shooter is excluded or the shell would trip on its own tank
  12px off the barrel, and tracers are excluded because detonating an aiming
  aid early just loses the trace you fired it for.

Determinism: FIRE_SYNC carries no new field. Both fire paths call armTrigger()
against the inventory every client already replicates - the same assumption the
existing client-side ammo decrement makes - and TRIGGER_PRIORITY is a fixed
order rather than a player choice, so every client arms the same trigger for
the same shot. The proximity check walks the roster in index order using only
+ - * and a comparison, so it trips on the same substep everywhere. Replay
identity is asserted for 4 weapons x 3 trigger states, plus a control that a
triggered shot actually differs from an untriggered one - otherwise those 12
replays would pass on a trigger that did nothing.

The HUD reads its [PROX]/[CONTACT] badge off TRIGGER_PRIORITY rather than a
second list, so it cannot advertise a trigger different from the one that will
be spent.
